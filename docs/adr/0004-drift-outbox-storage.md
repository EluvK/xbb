# 0004: Drift 响应式存储与单事务 Outbox 日志流持久化

## 决策背景与结论
为解决手写 SQL 字符串易错、缺乏编译期检查，以及手写事件广播易漏刷的问题，决定采用 Drift 强类型 Schema 与响应式流 (`watchQuery`)，并在单事务中原子提交业务实体变更与 Outbox 待发变更记录 (`saveEntityWithOutbox` / `persistPutRaw`)。核心原因在于单事务落盘能够确保本地离线业务写入与待同步日志绝对一致，从底层彻底根除因应用闪退或网络离线导致本地数据已更新但同步队列丢失的致命问题。

## 被否决的备选方案 (Rejected Alternatives)
- **手写 sqflite 原始 SQL 配合全局字符串事件总线**: 缺乏编译期类型检查，查询与刷新解耦容易发生漏刷和重复渲染。
- **纯内存暂存同步待发队列 (不落盘)**: 应用异常崩溃或被系统清理时，未上云的变更记录将永久丢失。
