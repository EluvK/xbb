# 0003: 打卡本地时区单次判定与禁止预打卡

## 决策背景与结论
每日习惯打卡核心在于忠实记录用户的实际习惯养成行为。决定采用设备所在地的自然日期 `localDayKey` (`yyyy-MM-dd`) 作为幂等唯一性约束，强制限定每个打卡事件每天至多产生 1 条有效记录，允许对过去日期补打卡，但严格禁止向未来日期预打卡或补打事件创建之前的日期。核心原因在于以用户肉身体感的本地自然日划分打卡周期符合人类直觉，且禁止提前透支打卡以维护习惯养成的契约性。

## 被否决的备选方案 (Rejected Alternatives)
- **统一以服务端 UTC 日期划分每日打卡窗口**: 跨时区用户在当地清晨或深夜打卡时，将因 UTC 日期漂移导致打卡归属错误（如东八区清晨打卡被判定为昨天）。
- **开放未来日期预打卡**: 严重违背“打卡即记录已发生事实”的领域语义，容易导致系统退化为无约束的待办清单。
