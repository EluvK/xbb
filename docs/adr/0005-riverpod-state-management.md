# 0005: 采用 Riverpod 替代 GetX 作为全局状态管理底座

## 决策背景与结论
为了提升客户端架构健壮性与单测隔离能力，决定全面废弃 GetX，采用 `flutter_riverpod` + `riverpod_annotation` 作为应用唯一状态管理底座。核心原因在于 GetX 依赖隐式全局单例与无上下文依赖查找，在多窗口、异步测试与深层组件树中极易引发内存泄漏与生命周期混乱；Riverpod 提供确定性的编译期生命周期安全 (`autoDispose`)、单向数据流与天生支持 override 的可测试性。

## 被否决的备选方案 (Rejected Alternatives)
- **继续保留 GetX**: 无法与 Drift 响应式流优雅融合，且全局隐式依赖注入导致模块高耦合、异步单测极度脆弱。
- **BLoC / Redux 架构**: 样板代码过多、概念过载，对小型个人生产力工具模块侵入性过强，开发心智负担高。
