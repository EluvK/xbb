# 0001: SQLite 按用户 ID 物理目录隔离

## 决策背景与结论
客户端需支持多账号切换并确保本地数据绝对隔离。决定采用 `<db_dir>/<user_id>/app_v2.db` 目录树结构对各用户数据进行物理单库隔离，未登录会话使用纯内存数据库 (`openInMemory()`)。核心原因在于物理目录隔离能彻底根除因 SQL 条件遗漏导致的跨账号数据串扰，支持原子级注销清理，同时单用户单库结构让本地业务表写入与 Outbox 变更日志能够在单一数据库事务内原子提交，杜绝多库分布式事务问题。

## 被否决的备选方案 (Rejected Alternatives)
- **单库多租户 (在所有表中增加 `user_id` 列)**: 开发疏忽极易导致全局查询越权泄漏，且清理指定用户数据时需跨表执行大量级联 DELETE 操作，安全性极差。
- **按业务模块分库 (如 `<user_id>/notes.db`, `<user_id>/task.db`)**: 无法在单个 SQLite 事务中同时持久化业务变更与统一 Outbox 变更日志，面临分布式事务不一致风险。
