# 0001: SQLite 按用户 ID 物理分库隔离

## 决策背景与结论
客户端需支持多账号切换并确保本地数据绝对隔离。决定采用 `<db_dir>/<user_id>/<feature>.db` 目录树结构对各用户不同业务模块进行物理分库，而非单库逻辑多租户。核心原因在于物理分库能彻底根除因 SQL 条件遗漏导致的跨账号数据串扰，且用户注销或清空数据时可直接原子级删除目录，极大降低数据运维与审计复杂度。

## 被否决的备选方案 (Rejected Alternatives)
- **单库多租户 (在所有表中增加 `user_id` 列)**: 开发疏忽极易导致全局查询越权泄漏，且清理指定用户数据时需跨表执行大量级联 DELETE 操作，性能与安全性极差。
- **统一大单库分表 (如 `user_123_notes`)**: 动态 DDL 复杂度高，不利于 `@Repository` 代码生成器自动化管理静态迁移与建表逻辑。
